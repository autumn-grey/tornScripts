# tornScripts

Userscripts for [Torn.com](https://www.torn.com), written in TypeScript and built to standalone `.user.js` files.

## Layout

```
src/
  shared/           # code used by more than one script — no meta.json
  <script-name>/
    meta.json       # userscript metadata block
    index.ts        # entry point
dist/               # BUILD OUTPUT — committed, never hand-edited
pages/              # standalone HTML tools, opened straight from disk, not built
```

A directory under `src/` is treated as a script if it contains `meta.json`. Anything else (like `shared/`) is ignored by the build.

## Generated files — do not edit

`dist/*.user.js` is generated by `build.mjs`. Editing it is pointless; the next build overwrites it. Edit `src/` and rebuild.

`dist/` **is committed**, unlike normal build output. Tampermonkey installs and GreasyFork syncing both read raw GitHub URLs, so the built files have to exist in the repo.

## Build

```
npm run build      # one-off
npm run watch      # rebuild on save
npm run typecheck  # tsc --noEmit, no output written
```

Output is **not minified**, deliberately — GreasyFork rejects minified or obfuscated source.

## Versioning

`version` in a script's `meta.json` becomes its `@version`. Tampermonkey only pulls a new copy when that number goes up, so any change reaching `dist/` needs a bump — but **bump the patch number**. Fixes, reworked internals and behaviour changes to an existing feature are all patch bumps: `0.16.3` → `0.16.4`.

Minor bumps are for a **new feature** — a new entry in `settings.ts` that can be switched on and off, or a new script. Nothing else earns one. Do not reach for a minor bump because a change feels large or alters what the user sees; fixing a feature so it finally works is still a fix.

Bump only the script that changed. The versions across `src/*/meta.json` are independent and are not kept in step.

## Comments

Standard professional practice, which is also the style already in `src/`:

- Say **why**, not what. The code states what it does; a comment earns its
  place by giving the reason, the constraint, or the thing that caught us out.
- Every file opens with a line saying what it is for. Every exported function,
  and every internal one that is not obvious, gets a `/** ... */`. One line
  where one line does, a paragraph where the reasoning needs it.
- Write down the facts a reader cannot see from here: a Torn quirk, the shape
  of a response, a browser behaviour being relied on. Those are the comments
  worth having.
- No commented-out code, no bare `TODO`, no restating the signature in prose.
- Keep them true. A stale comment is worse than none, so changing the code
  means changing the comment above it.

## Constraints

**GreasyFork:** no minified/obfuscated source. `@require` only from allowlisted CDNs (jsdelivr, cdnjs, unpkg, ajax.googleapis.com, code.jquery.com), always version-pinned, never from our own domain.

**Torn:** follows Torn's scripting rule (Rules page, "Scripting abuse"). In practice:

- Data comes from the API, or from the page the player loaded and is looking at. Never scrape a page they are not viewing.
- A request to Torn's own (non-API) pages must be started by the player, one click for one action. A button that does one thing when clicked is fine. Requests a script sends by itself, on a timer, on page load, or as extra requests on top of the one the player asked for, are not.
- Nothing from an unfocused tab: no reading it to send elsewhere, no alerts or attention-grabbing from it.
- Display changes (greying out, warnings, overlays, injected info) are always fine.

**API keys:** never written to a file in this repo. `.gitignore` blocks the usual accidents, but the rule is that keys never touch disk here at all. In the browser, a script keeps its key in `GM_setValue` when it already has GM grants, or in `localStorage` when it runs with `@grant none` (Autumn's UI Enhancer: adding a grant would sandbox it and cut its fetch, XHR and scroll patches off from Torn's own code).

## Torn specifics

Travel times vary per user (private island, airline job perks, travel items). Read them from the page rather than hardcoding a table — a hardcoded table is wrong for most users and goes silently stale.

Torn's DOM class names are hashed and change between deploys (`class="foo___aB3xY"`). Match on stable prefixes or structure, never on a full hashed class name. Expect selectors to be the thing that breaks, and keep them together at the top of a file rather than scattered through it.
